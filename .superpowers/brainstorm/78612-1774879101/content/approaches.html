实现方案对比

三种架构策略

A

渐进式重构

保留现有组件结构，逐个替换样式，最小化代码变更风险

B

设计系统优先

先建立完整的设计系统基础（tokens、主题、基础组件），再重构页面组件

C

组件重建

基于设计稿重写所有组件，完全抛弃旧代码，确保像素级还原

💡 推荐：方案 B

设计系统优先

平衡还原度与可维护性的最佳选择

实施步骤：
  1. Phase 1: 设计系统
    • Tailwind 配置（颜色、字体、圆角）
    • 主题切换机制（data-theme）
    • 本地字体文件引入
    • 基础 UI 组件库
  2. Phase 2: 布局组件
    • SideNavBar（固定宽度 280px）
    • TopNavBar（毛玻璃效果）
    • 主内容区布局容器
  3. Phase 3: 页面组件
    • LaunchPad（Bento Grid）
    • ChatArea（消息流）
    • Settings（Agent/LLM 配置）
  4. Phase 4: 细节打磨
    • 动画过渡效果
    • 交互状态（hover/active）
    • 光晕背景效果
